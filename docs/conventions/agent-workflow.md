# 에이전트 작업·검증·버전 관례

## 작업 수명주기

1. 감독 에이전트가 승인된 설계에서 하나의 독립 작업을 정의한다.
2. `docs/AGENT_WORKLOG.md`에 `PLANNED` 상태로 기록한다.
3. 담당 에이전트가 하네스 버전, 역할, 소유 파일과 비범위를 수용한다.
4. 담당 에이전트가 테스트 우선 방식으로 구현하고 자체 검증한다.
5. 감독 에이전트가 코드 또는 화면을 독립 검증한다.
6. 통과하면 `PASSED`, 실패하면 `REVISION`으로 기록한다.
7. 수정 후에도 중대한 문제가 남으면 `BLOCKED`로 기록하고 사용자에게 알린다.

## 병렬 작업 조건

- 에이전트별 수정 파일이 겹치지 않아야 한다.
- UI와 로직 사이의 데이터 계약이 먼저 확정되어야 한다.
- 한 작업의 결과가 다른 작업의 입력이면 병렬화하지 않는다.
- 공통 설정과 문서는 감독 에이전트만 수정한다.

## 버전 증가

| 변화 | 증가 예시 |
|---|---|
| 개발 중 다음 검증 결과 | `0.4.0-dev.0` → `0.4.0-dev.1` |
| 주요 기능 검증 완료 | `0.4.0-dev.N` → `0.4.0` |
| 호환되는 기능 추가 | `0.4.0` → `0.5.0` |
| 호환되는 오류 수정 | `0.5.0` → `0.5.1` |
| 핵심 계약의 비호환 변경 | `0.x` 단계에서는 다음 minor, `1.x` 이후에는 major |

`VERSION`, `CHANGELOG.md`, 작업 기록은 같은 품질 게이트에서 갱신한다. Git 태그는 안정 버전에만 만든다.

## 커밋 후보 기준

- 승인된 범위만 변경됨
- 자동 하네스 검사 통과
- 관련 단위·통합 테스트 통과
- 화면 작업은 Figma 대조와 상태별 점검 통과
- 알려진 한계가 작업 기록과 변경 이력에 남음
- 사용자 소유의 무관한 변경이 포함되지 않음
