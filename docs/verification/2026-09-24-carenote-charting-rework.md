# CareNote 차팅 재작업 — 감독 검증

기준일: 2026-09-24. 기준 커밋 `9088607d`, 작업 브랜치 `codex/1.0-carenote-suite`. 버전 1.0.3. 현재 상태: 로컬 품질 게이트 및 공개 배포 확인 완료.

## 사용자 피드백과 결정

프로젝트 소유자가 `잠 못잠` 입력에 O/A/P가 모두 `[직접 확인·작성 필요]`로 나오는 화면을 지적하고, 기존 차팅 담당에게 재작업을 요청했다. 이는 추가 사용자 인터뷰나 임상 효과 검증이 아니다.

담당의 원본 앱 대조 결과, 기존 문장화에는 입력에 없는 확인 행위·계획이 포함되었다. 그 결과 전체를 복제하지 않고 **제공된 사실의 문장화 → 명시 채택 → 원문 비교 → 명시 기록 추가**를 복구했다. 원본 차팅 앱은 수정하지 않았다.

대안과 이유:

- 원본의 완성형 SOAP 복제: 입력에 없는 관찰·계획까지 사실처럼 생성하므로 제외.
- 원문 복사와 빈 O/A/P 유지: 사용자가 지적한 작성 부담을 해소하지 못하므로 제외.
- 제공된 사실의 섹션만 구성: 감독이 기존 가역적 자율 진행 위임 아래 CareNote 합성 데이터 데모에 한해 결정. 실제 병원 기록 정책이나 사용자 승인된 임상 표준으로 표현하지 않는다.

## 실제 변경 범위

- 지원 단문에 규칙 기반 문장 추천. `잘잠` → `S: 잘 잤음.`, `잠 못잠` → `S: 잠을 이루기 어려움.`, `통증 3점` → `S: 통증 정도 3점.`, `오심 없음` → `S: 오심 없음.`
- NRS는 입력에 있을 때만 유지. 배액량은 제공된 숫자·단위로 O 섹션 구성. 복합·정정·미지원 표현은 원문 유지.
- 채택 전 본문 변경 없음. 채택 후 원문 비교 표시. 기록 추가는 별도 사용자 동작이다.
- 별도 CareNote 검증기: 최소 하나의 내용 있는 SOAP 섹션, 순서·중복·빈 항목·명시 미완성 표시·시간 검증. 원본 4항목 검증기는 유지.
- 랜딩 예시와 FAQ를 위 동작으로 동기화. 스타일·레이아웃·API·환자 데이터·워크스페이스 저장 방식은 변경하지 않았다.

## 독립 리뷰와 수정

초기 독립 검토는 Critical 0 / Important 0 / Minor 2. 정상 수기 문구 `[검사 결과 확인함]`이 잘못 차단되고, 여러 줄 미완성 표시/메타 문구만 있는 섹션이 통과하는 사례를 재현했다. 같은 담당에게 검증기 및 해당 테스트 두 파일만 수정하도록 FIX ROUND 1을 지시했다. 담당은 35건 중 7건 실패 RED → 35건 통과 GREEN을 보고했다. 독립 재검토가 검증기 35건과 별도 정상 6종·미완성 7종을 직접 실행해 두 건 해결, 해당 범위 잔존 지적 없음으로 판정했다.

## 감독이 직접 수행한 검사

- 공개 구버전의 `잠 못잠` 회귀 E2E RED: 새 문장 대신 원문과 미완성 세 항목이 표시되어 예상대로 실패.
- 수정본 로컬 차팅 5건 + 랜딩 7건 E2E 통과. 최초 테스트의 `alert` 선택자가 Next 경로 알림과 중복되어 테스트만 차팅 영역 안으로 한정했다. 제품 결함으로 분류하지 않는다.
- 실제 브라우저: 추천, 채택 후 원문 비교, 명시 추가 뒤 타임라인 1건과 시점 갱신 확인. 390px 모바일에서 추천 문장·채택 버튼 줄바꿈 및 표시 확인.
- Python: `.venv/carenote/Scripts/python.exe -m unittest discover -s tests -q` — 155건 통과. 같은 실행기로 harness 통과.
- 전체 Vitest: `node node_modules/vitest/vitest.mjs run` — 33파일 473건 통과(37.99초).
- 전체 E2E: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3017`, `node node_modules/@playwright/test/cli.js test --workers=1` — 86건 통과(약 1.3분): 차팅 5, 랜딩 7, CareNote 실제 API 6, 기존 인계/안내 68. 검증기 최종 수정과 실행 시점이 일부 겹쳤으며, 최종 검증기 고정본의 경계는 위 단위·독립 재검토로 확인했다. 배포 후 신규 차팅 흐름을 다시 검사한다.
- 전체 ESLint, Next production build(TypeScript 포함), 별도 TypeScript noEmit 통과. 버전 1.0.3 반영 후 harness 재검사 통과.
- Vite 설정 및 Starlette/httpx의 미래 호환성 경고는 기존 비실패 경고로 남으며 범위 밖 설정을 변경하지 않았다.
- 최종 파일 동결 및 커밋 후 CareNote 전체(차팅5 + 랜딩7 + 실API6) E2E 18건을 재실행해 통과했다(13.6초).

## 한계

지원하는 짧은 입력만 처리하는 규칙 기반 기능이며 LLM/API 기반 차팅이나 모든 자연어 자동 기록이 아니다. 원문 비교 표시는 일시적 UI 상태이지 영구 감사로그가 아니다. 명시 추가된 기록도 페이지 메모리의 미서명 합성 시연 기록이며 새로고침하면 사라진다. 형식 검사·자동 테스트 통과는 임상적 완전성이나 사용성·시간 절감 효과의 입증이 아니다.
