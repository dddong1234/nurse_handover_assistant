# 003. 첫 방문 업무 흐름 안내

날짜: 2026-09-14. 사용자 승인: 4단계 안내 제안 후 `ㄱㄱ`.

## 문제와 근거

사용자가 직접 "딱 들어왔는데 뭘 봐야할지 뭘 해야할지를 모르겠음"이라고 보고했다. 기존 UI는 환자 목록, 비교 결과, 검토 패널을 동시에 제공하지만 시작 위치나 읽는 순서를 안내하지 않는다. 이는 이번 변경의 직접 근거이며, 아직 복수 사용자 실험으로 빈도나 개선 효과를 측정한 것은 아니다.

## 결정

첫 접속에 짧은 시작 안내를 제공하고, `담당 환자 → 인수인계 범위 → 변화·근거 → 요약·검토` 순서로 실제 화면 영역을 가리킨다. 사용자는 언제든 건너뛰거나 상단 `화면 안내`로 다시 열 수 있다. 안내 본문은 기존 화면에서 문제로 지적된 작은 글자를 반복하지 않도록 14–16px 기준으로 구현한다.

휴무 복귀의 근무 준비 화면은 SBAR 비교 화면과 다르므로 현재 범위와 탭에 따라 설명을 바꾼다. 직전 교대의 `근거 상세`, 휴무 복귀의 `근거 보기` 등 실제 버튼명을 사용한다. 안내가 환자나 모드를 자동 선택하지 않도록 해 재실행할 때도 현재 작업 맥락을 유지한다.

최초 안내 완료 여부는 `nurse-handover:onboarding:v1`이라는 브라우저 localStorage 키에 `dismissed` 또는 `completed`만 저장한다. 환자 식별자, 기록, 검토 상태는 저장하지 않는다. 임상 초안과 확인 표시는 기존 sessionStorage 경계를 유지한다. localStorage 이용이 제한된 브라우저에서도 안내를 닫고 제품을 사용할 수 있어야 한다.

## 선택 이유와 대안

- 별도 매뉴얼 페이지: 실제 화면과 설명을 번갈아 확인해야 하므로 첫 진입 문제를 충분히 해결하지 못한다.
- 모든 영역에 상시 설명: 이미 밀도가 높은 화면의 읽을거리를 늘리므로 짧은 재실행 가능한 안내를 선택한다.
- 강제 조작 미션: 기존 기록·검토 상태를 바꿀 수 있어 이번에는 읽기 중심 가이드를 선택한다.
- 매번 자동 표시: 반복 사용을 방해하므로 안내 선호만 브라우저에 기억한다.

디자인은 기존 MCP 검토가 끝난 Figma node 39:3의 토큰을 재사용한다. 이번 재조회는 Starter 호출 한도로 실패했으며 새 Figma 화면을 확인했다고 주장하지 않는다.

## 검증과 효과 측정

출시 게이트는 최초 진입, 건너뛰기, 완료 후 미노출, 재실행, 키보드 종료·포커스 복귀, 저장소 실패, 상태 보존, 390/960/1440px 가독성과 영역 가림 검사다. 브라우저 가이드를 마쳤다는 사실은 임상 항목 확인이나 처치 완료를 의미하지 않는다.

후속 사용성 실험은 첫 환자 선택까지의 시간, 올바른 범위 선택 성공률, 첫 근거 열기까지의 시간과 도움 요청 횟수를 안내 제공 전후로 비교한다. "30초 안내"는 짧은 길이를 지향하는 설계 목표이며 검증된 시간 절감 수치가 아니다. 이번 구현에 사용자 행동 수집이나 외부 분석 도구는 추가하지 않는다.
