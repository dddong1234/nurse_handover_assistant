# CareNote 제품 소개 페이지 리디자인

기준일: 2026-09-23. 상태: 구현·감독 로컬 검증 완료, 배포 결과는 별도 검증 기록 참고. 사용자 요청은 기존 랜딩을 상용 SaaS 소개 페이지처럼 개선하는 것이며, 실제 상용 운영으로 제품 범위를 바꾸는 것이 아니다.

## 관찰과 결정

공식 홈페이지를 검색하고 실제 브라우저 화면을 확인했다.

| 참고 | 가져오는 원칙 | 가져오지 않는 요소 |
|---|---|---|
| [Linear](https://linear.app/) | 짧은 큰 제목, 제품 화면 자체를 주요 시각 요소로 사용 | 검정 브랜드 복제, 고객 로고 및 성과 |
| [Ramp](https://ramp.com/) | 직접적인 가치 제안과 명확한 체험 행동 | 가입 폼, 확인되지 않은 수치·고객·가격 |
| [Heidi](https://www.heidihealth.com/) | 의료진의 업무 중심 설명, 제품별 미리보기 전환 | 의료 AI 능력·인증·효과를 CareNote의 실적으로 전용 |

UI/UX Pro 검색에서 제품 데모 중심 패턴을 선택했다. 최초 일반 추천의 인증 배지·고객 로고·인디고 색상·과한 모션은 이 제품의 근거와 브랜드에 맞지 않아 제외했다. frontend-design의 위계·타이포그래피·일관된 시각 언어 원칙을 적용한다.

Figma MCP의 `KpybGW6Y8u9TyPSv61OcM9`, node `39:3`을 다시 조회했다. 네이비 `#0B2339`, 청록 `#176B87`, 배경 `#F7F9FB`, 흰 패널, 선 `#DCE3EA`, 선택 `#EAF5F8`과 임상 UI 맥락을 유지한다. 원본 Figma에 있지만 현재 제품에 없는 기능은 소개하지 않는다.

## 정보 구조

1. 큰 제목과 한 문단 설명, 데모 체험 및 제품 둘러보기.
2. 같은 합성 환자 맥락의 근무 준비 / 원본 근거 / 간호기록 미리보기.
3. 짧은 핵심 기능 설명, 기간과 근거 연결 및 수기 확인이 필요한 SOAP 흐름.
4. 실제 저장·생성 범위를 설명하는 FAQ와 마지막 체험 링크.

미리보기는 실제 작업공간과 구분된 예시다. CBC WBC 12.1과 08:20 기록 시각은 기존 합성 사례를 사용한다. 과거 검사값이나 투약 사실을 새로 만들지 않는다. `통증 3점`의 미제공 O/A/P는 직접 확인·작성 필요로 남긴다. 미리보기 탭은 키보드로 조작하고 자동 전환하지 않는다.

## 범위와 협업 계약

- 하네스 1.2.0. 프런트엔드 구현 담당의 소유 파일은 LandingPage 컴포넌트·CSS Module·단위 테스트 3개다.
- 감독은 레퍼런스·Figma 확인, 별도 E2E, 코드/화면 검토, 문서·버전·배포를 담당한다.
- 기존 작업공간, 임상 로직, API, 환자 데이터, 저장 정책, 기존 두 서비스의 배포는 변경하지 않는다.
- 디자인 재확인 질문은 사용자의 기존 자율 진행 지시에 따라 생략했다. 되돌릴 수 없는 변경이나 새로운 유료·개인정보 처리는 범위 밖이다.
- 사용자가 앞서 제거 요청한 장식용 영문 소제목과 중복 안내를 다시 늘리지 않는다.

## 검증 계획과 초기 근거

- 신규 감독 E2E의 키보드 탭 검사: 변경 전 `제품 미리보기` 탭이 없어서 실패함을 확인했다. 기존 기능 오류가 아니라 새 계약의 RED 확인이다.
- 구현 후 단위 검사, 린트, 타입 검사, 빌드, Python 검사와 하네스 및 CareNote 실 API E2E를 실행한다.
- 375/768/1024/1440의 탭·버튼 경계와 가로 넘침을 검사하고, 실제 데스크톱·모바일 화면을 별도 검토한다.
- 자동 검사와 감독 화면 검토는 사용자 효과·전환율·시간 절감 검증이 아니다. 이번 작업에서 그런 성과를 측정하거나 주장하지 않는다.

## 감독 검토에서 발견한 사항

첫 구현의 기능 검사 428건과 E2E 80건은 통과했지만, 실제 1440/375 화면과 독립 코드 리뷰에서 링크 색상 reset의 우선순위가 CTA 흰 글자를 덮는 문제를 발견했다. 별도 E2E에서 대비 1.151:1로 실패함을 확인하고 같은 담당에게 수정 요청했다. 미리보기 보조 글자, 숨긴 줄바꿈 뒤 문장 공백, sticky 헤더와 앵커도 함께 점검 대상으로 지정했다. 따라서 최초 자동 검사 결과만으로 릴리스하지 않는다.
