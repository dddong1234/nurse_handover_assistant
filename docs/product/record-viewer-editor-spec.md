# 가상 원본 기록 조회·입력 샌드박스 명세

## 1. 목적

사용자가 선택한 가상 환자의 이전·현재 원본 차트를 구조화된 EMR 화면으로 확인하고, 현재 기록을 직접 수정한 뒤 기존 차이 비교와 근거 요약을 다시 실행할 수 있게 한다.

이 기능은 비교 결과의 출처를 확인하고 제품의 핵심 가치를 직접 체험하게 하는 포트폴리오 시연 흐름이다. 실제 환자정보 저장, 운영 EMR 쓰기 연동, 의료적 판단 자동화는 포함하지 않는다.

## 2. 승인된 제품 결정

- 데이터는 저장소에 포함된 가상 환자 기록만 사용한다.
- 사용자가 적용한 현재 기록은 브라우저 `sessionStorage`에만 유지한다.
- 비교 요청이 성공한 경우에만 편집 기록과 비교 결과를 함께 적용한다.
- 비교 요청이 실패하면 기존 검증 결과를 유지하고 편집 화면에서 오류와 재시도 방법을 알린다.
- 영구 데이터베이스, 로그인, 사용자 간 공유는 이번 범위에 포함하지 않는다.
- OpenAI 키가 없거나 호출이 실패하면 기존 deterministic 요약을 사용한다.

## 3. 핵심 사용자 흐름

1. 환자 컨텍스트 아래의 `원본 기록` 중앙 모듈 탭을 누른다.
2. 인라인 작업공간에서 `이전 기록`과 `현재 기록`을 전환해 확인한다.
3. `현재 기록`에서 활력징후, 진단, 투약, 간호기록, 기록 시간을 수정한다.
4. `변경사항 비교`를 누른다.
5. 서버 비교가 성공하면 `인수인계 비교` 탭으로 이동하고 변화 행과 인계 요약이 새 결과로 갱신된다.
6. 해당 환자의 기존 검토 완료 상태와 근거 선택은 새 비교 결과에 맞게 초기화된다.
7. `데모 초기화`를 누르면 해당 환자의 번들 가상 기록으로 돌아간다.

## 4. 정보 구조

```text
통합 임상 워크벤치
┌──────────┬──────────────────────────────┬──────────────┐
│ 담당환자 │ 환자 컨텍스트                │ 인계 검토    │
│          │ [인수인계 비교] [원본 기록]  │ SBAR·근거    │
│          │ ─ 환자정보 (읽기 전용)       │              │
│          │ ─ 활력징후·진단·투약·기록    │              │
│          │ [초기화] [변경사항 비교]      │              │
└──────────┴──────────────────────────────┴──────────────┘
```

- 데스크톱·태블릿: 세 레일은 유지하고 원본 기록이 중앙 모듈 전체를 사용한다.
- 모바일: 담당 환자·환자 컨텍스트·중앙 모듈·인계 검토가 세로로 쌓이며 원본 기록은 전체 폭을 사용한다.
- 이전 기록: 모든 필드를 읽기 전용으로 표시한다.
- 현재 기록: 환자 ID·이름·병실·성별·나이는 읽기 전용, 임상 기록 필드는 편집 가능하다.
- 원본 JSON 문자열은 사용자 화면에 노출하지 않는다.

## 5. 시각 방향

통합 워크벤치의 Figma 기반 색상·타이포그래피 토큰을 유지한다.

- Header `#0b2339`
- Canvas `#f7f9fb`
- Surface `#ffffff`
- Ink `#17202a`
- Muted `#7b8c9d`
- Line `#dce3ea`
- Primary `#176b87`
- Critical `#c83b3b`
- Watch `#b86b00`
- UI: Inter 계열, 데이터·시간: JetBrains Mono 계열

시그니처 요소는 **차트 장부형 구획선**이다. 장식용 카드 묶음 대신 실제 EMR의 기록지를 연상시키는 얇은 구획선, 섹션 코드(`V/S`, `DX`, `MED`, `NOTE`)와 고정된 기록 시각을 사용한다. 시각적 강조는 `변경사항 비교` 행동에만 집중한다.

## 6. 편집 계약

```ts
type DemoPatientRecord = {
  patient_id: string;
  name: string;
  room_no: string;
  age: number;
  sex: string;
  diagnosis: string[];
  vitals: Record<string, number>;
  medications: Array<{ name: string; route: string; frequency: string }>;
  notes: string[];
  updated_at: string;
};
```

- 활력징후: 수축기/이완기 혈압, 맥박, 호흡, 산소포화도, 체온 숫자 입력
- 진단: 한 줄에 한 항목
- 투약: 약명, 경로, 빈도 단위의 구조화된 행 입력
- 간호기록: 한 줄에 한 항목
- 기록 시각: `datetime-local` 입력을 ISO 8601 문자열로 변환해 비교 API에 전달
- 빈 진단·투약·간호기록 행은 전송 전에 제거
- `patient_id`는 편집할 수 없고 이전 기록과 동일해야 한다.

## 7. 상태와 실패 처리

- 저장 키: `nurse-handover:record-drafts:v1`
- 저장 단위: 환자 ID별 적용된 현재 기록
- 잘못되거나 이전 형식인 세션 값은 무시하고 번들 기록을 사용한다.
- 비교 중에는 편집·초기화·비교 버튼을 잠그고 `비교 중`을 표시한다.
- HTTP·네트워크·응답 검증 실패 시 원본 기록 모듈과 draft를 유지하고 `비교하지 못했습니다. 기록을 확인한 뒤 다시 시도하세요.`를 표시한다.
- 새 비교 성공 시 기존 검토 완료, 원본 확인 체크, 선택 근거와 간호사 메모를 초기화한다.
- 환자를 바꾸면 `인수인계 비교` 탭으로 돌아가 다른 환자의 미적용 draft를 노출하지 않는다.

## 8. 접근성과 검증 기준

- 중앙 모듈은 `role="tablist"`·`role="tab"`·`role="tabpanel"` 관계와 환자명 기반 accessible name을 제공한다.
- ArrowLeft/ArrowRight, Home/End로 비교·원본 기록 탭을 이동하고 선택 탭에 포커스를 유지한다.
- SBAR 근거 링크를 누르면 비교 탭으로 전환한 뒤 정확한 변화 행에 포커스를 이동한다.
- 모든 입력은 화면에 보이는 `<label>`과 연결한다.
- 390px, 1024px, 1440px에서 가로 스크롤이 없어야 한다.
- 편집한 P001 체온이 비교 요청 payload에 반영되고 성공 응답이 화면에 표시되는 E2E 경로를 검증한다.

## 9. 비범위

- 실제 환자정보와 운영 EMR 연결
- 서버 파일 쓰기와 영구 데이터베이스
- 인증·권한·감사로그
- 자유 형식 JSON 편집기
- 새로운 임상 변화 규칙 또는 AI 판단
