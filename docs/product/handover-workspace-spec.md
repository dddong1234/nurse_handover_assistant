# Nurse Handover Workspace 제품·화면 명세

- 상태: 구현 기준 초안
- 작성일: 2026-08-28
- 근거 UI: Figma Make `Nurse EMR Interface Design`
- 대상 배포: Vercel

## 1. 제품의 한 문장 목적

일반 성인병동의 교대 인수인계 전에 간호사가 환자 기록의 이전 시점과 현재 시점 사이에서 달라진 사실을 빠르게 찾고, 근거를 확인한 뒤 전달 가능한 요약으로 정리하도록 돕는다.

이 제품은 EMR을 대체하거나 임상 판단을 자동화하지 않는다. 모든 데이터는 가상 데이터이며, 최종 확인과 전달 책임은 사용자에게 있다.

## 2. 이번 단계의 기준 결정

| 항목 | 기준 | 이유 |
|---|---|---|
| 대표 환경 | 일반 성인병동(Med-Surg) | 현재 5인 가상 데이터셋이 여러 일반병동 시나리오를 포함하고 ICU 전용 필드를 갖지 않는다. |
| 인수인계 유형 | 교대 인수인계 | 현재 snapshot 비교 모델과 가장 자연스럽게 대응한다. |
| 요약 구조 | 변화 우선 SBAR | 전체 차트를 다시 요약하기보다 이번 교대에서 달라진 사실을 먼저 보여주는 것이 프로젝트 핵심과 일치한다. |
| 사실 판정 | deterministic 비교 엔진 | 누락·환각을 줄이고 모든 문장을 원본 변화에 추적 가능하게 한다. |
| LLM 역할 | 검출된 사실의 문장화만 담당 | 모델이 새로운 임상 사실이나 중요도를 만들지 않게 한다. |
| 영속성 | 읽기 전용 fixture + 브라우저 세션 | Vercel 1차 포트폴리오 범위에서 데이터베이스 도입을 피한다. |

대표 환경과 인수인계 형식은 실제 병원 사용자 검증 후 변경할 수 있는 제품 가정이다. 코드에서는 병동명이 핵심 로직에 결합되지 않게 한다.

## 3. Figma에서 채택하는 것과 채택하지 않는 것

### 채택

- 흰색 표면과 청색 주 행동색을 중심으로 한 고밀도 임상 UI
- 상태를 색상만이 아니라 텍스트와 기호로 함께 표현하는 방식
- 환자명, 병실, 식별자, 담당의, 알레르기를 한 영역에서 확인하는 환자 컨텍스트
- `Inter`를 UI 본문에, `JetBrains Mono`를 시각·식별자·수치에 사용하는 타이포 역할
- Critical, Watch, Stable의 의미 색상 팔레트와 색상 외 라벨 병행 원칙

### 채택하지 않음

- Overview, Vitals, Medications, Notes의 범용 EMR 4탭 구조
- 현재 수치만 크게 보여주는 바이탈 카드 중심 구성
- 투약 수행, 간호 기록 작성 등 실제 EMR 입력 기능의 광범위한 재현
- 전체 차트를 탐색해야 인수인계 결과에 도달하는 흐름

## 4. 화면의 단일 핵심 작업

선택한 환자의 **이전 기록과 현재 기록의 차이를 검토하고 인수인계 요약을 확정한다.**

화면 진입 후 사용자는 다음 순서로 작업한다.

1. 환자 큐에서 변화 건수와 미검토 상태를 보고 대상을 선택한다.
2. 비교 기준 시각이 맞는지 확인한다.
3. 중요한 변화와 일반 변화를 검토한다.
4. 각 변화의 이전값, 현재값, 원본 필드와 기록 시각을 확인한다.
5. 자동 생성된 SBAR 초안을 검토한다.
6. 모든 근거가 포함됐는지 확인하고 `검토 완료` 상태로 바꾼다.

## 5. 정보 구조

데스크톱 1440px 기준의 3영역 작업공간을 사용한다.

```text
┌──────────────┬──────────────────────────────────┬──────────────────────┐
│ 환자 큐      │ 비교 작업공간                    │ 인수인계 초안         │
│ 검색/필터    │ 환자 컨텍스트 + 비교 기준 시각   │ SBAR 섹션             │
│ 변화/미검토  │                                  │ 근거 포함률            │
│              │  이전  ── 변화 ──>  현재        │ 편집/재생성/fallback   │
│              │  중요 변화                      │ 검토 완료              │
│              │  일반 변화                      │                       │
│              │  데이터 부족/변화 없음          │                       │
└──────────────┴──────────────────────────────────┴──────────────────────┘
```

### 5.1 환자 큐

- 검색: 이름, 환자 ID, 병실
- 기본 정렬: 미검토 중요 변화 > 미검토 일반 변화 > 검토 완료
- 각 행: 병실, 환자명, 주요 진단, 변화 건수, 최고 중요도, 검토 상태
- 선택 환자는 배경색과 좌측 3px 주 행동색 선으로 표시한다.
- `변화 없음`과 `비교 데이터 없음`을 별도 상태로 표시한다.

### 5.2 환자 컨텍스트 헤더

- 환자명, 성별/나이, 병실, 환자 ID
- 주요 진단
- 비교 기준: 이전 기록 시각 → 현재 기록 시각
- 알레르기 데이터가 스키마에 없으면 임의로 만들지 않고 `알레르기 데이터 없음`을 표시한다.
- 현재 fixture에 없는 담당의, code status, isolation은 이번 단계에서 표시하지 않는다.

### 5.3 비교 작업공간

핵심 시각 장치는 **Shift Seam**이다. 이전과 현재 사이의 세로 경계에 변화 방향을 고정해 간호사가 좌우 값을 읽는 동안 시간축을 잃지 않게 한다.

비교 작업공간은 화면의 주 표면이다. 환자 컨텍스트 바로 아래에 `이번 근무 변화` 스트립을 두고 `이전 시각 → 현재 시각`, 전체 변화 건수, 먼저 확인할 변화 건수를 한 번에 보여준다. 변화 항목은 독립 카드가 반복되는 인상보다 작업목록에 가까운 평면 행으로 표현하며, 근거 상세는 사용자가 펼치거나 요약의 근거 링크로 이동했을 때 강조한다.

변화 카드는 다음 정보를 가진다.

- 분류: 활력징후, 투약, 진단, 간호 메모
- 변경 유형: 추가, 중단, 변경, 삭제
- 검토 우선순위: high, medium, low
- 이전값과 현재값
- 수치 변화량 또는 변경 설명
- 근거: 원본 필드 경로와 양쪽 기록 시각
- 요약 포함 여부

검토 우선순위는 임상 중증도가 아니라 화면에서 확인할 순서다. 투약 추가·중단·변경과 진단 추가·삭제는 `high`, 활력징후 변화는 `medium`, 메모 추가·삭제는 `low`로 둔다. 값의 상승·하락 자체를 호전·악화로 표현하지 않는다.

### 5.4 인수인계 초안

우측 영역의 사용자-facing 명칭은 **인계 검토**로 한다. 이 영역은 비교 작업공간과 경쟁하는 문서 뷰가 아니라, 근거 포함률 확인 → SBAR 초안 검토 → 수기 Recommendation → 원본 확인 → 검토 완료 순서를 안내하는 작업 레일이다.

- Situation: 환자 식별, 병실, `MM/DD HH:mm → HH:mm` 형식의 교대 비교 구간과 핵심 변화 개수. 날짜가 바뀌면 양쪽 날짜를 모두 표시한다.
- Background: 기존/신규 진단과 주요 투약 변경
- Assessment: 활력징후와 새 간호 메모의 변화 사실
- Recommendation: 현재 데이터만으로 자동 생성하지 않는다. 대신 `간호사가 확인할 후속 항목`으로 표시하고 사용자가 직접 입력한다.
- 근거는 문장 아래의 `근거 N건` 접이식 영역에 배치한다. 기본 화면에서는 긴 근거 ID를 숨기고 `근거 1`과 같은 짧은 링크를 표시하되, 접근성 이름·툴팁·원문 변화 카드에는 전체 ID를 유지한다.
- 근거 링크는 같은 링크를 반복해 선택해도 대응하는 원문 변화 카드로 포커스를 다시 이동한다.
- `규칙 요약` 또는 `AI 요약` 출처를 임상 사용자용 명칭으로 표시한다.
- 기본 요청은 AI 문장화를 시도하고, AI 실패 또는 키 없음 상태에서는 규칙 기반 bullet을 그대로 사용하면서 실패 원인을 사용자용 문장으로 안내한다.
- `검토 완료`는 포트폴리오 데모의 브라우저 세션 상태만 변경한다.

## 6. 디자인 토큰

Figma Make의 청색·백색 임상 UI와 의미 색상 역할을 유지하되, 구현 시 아래 토큰을 단일 기준으로 사용한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `canvas` | `#F3F6F9` | 전체 작업 배경 |
| `surface` | `#FFFFFF` | 패널과 카드 |
| `ink` | `#182230` | 본문과 주요 수치 |
| `muted` | `#667085` | 보조 정보 |
| `line` | `#D8E0E8` | 구획과 입력 테두리 |
| `primary` | `#1769E0` | 선택·주 행동 |
| `critical` | `#C83B3B` | 즉시 검토 상태 |
| `watch` | `#B86B00` | 주의 상태 |
| `stable` | `#247A5A` | 완료·안정 상태 |

명시적인 임상 중증도 데이터가 없는 현재 fixture에서는 `critical`을 자동 적용하지 않는다. 화면의 `high` 검토 우선순위는 `watch`, `medium`은 `primary`, `low`는 `muted` 계열로 표현한다.

- UI 본문: `Inter`, 시스템 sans-serif fallback
- 수치·시간·ID: `JetBrains Mono`, monospace fallback
- 모서리: 패널 10px, 작은 상태 태그 999px
- 그림자보다 1px 선과 표면 대비를 우선한다.
- 애니메이션은 환자 전환과 요약 근거 하이라이트에만 120–180ms로 사용한다.
- `prefers-reduced-motion`에서는 전환을 제거한다.

## 7. 반응형 전략

- 1280px 이상: 3영역 동시 표시
- 960–1279px: 환자 큐 축소, 요약 패널을 우측 drawer로 전환
- 959px 이하: 환자 큐 → 비교 → 요약의 단계형 화면
- 최소 검증 폭: 390px, 1024px, 1440px
- 실제 간호사용 기본 환경은 데스크톱이며 모바일은 포트폴리오 탐색과 검토 보조 범위다.

## 8. 상태와 오류

- 로딩: 환자 큐 skeleton과 비교 영역의 시간축 자리 유지
- 변화 없음: `두 기록 사이에서 검출된 변화가 없습니다.`
- 이전 기록 없음: `비교할 이전 기록이 없습니다.`와 현재 기록 시각 표시
- API 실패: 규칙 기반 fixture 비교 결과 유지, AI 요약만 실패 배너 표시
- 데이터 누락: 누락 필드명을 밝히고 `데이터 부족`으로 분리
- 미지원 질문: 지원 가능한 필터를 제안하고 결과 없음과 구분

## 9. 접근성과 범위 고지

- 상태는 색상 외에 라벨과 아이콘/기호를 함께 사용한다.
- 모든 상호작용은 키보드로 가능하고 focus ring을 유지한다.
- 본문 대비는 WCAG AA를 목표로 한다.
- 환자 변경 시 환자명과 비교 시각을 화면 낭독기에 알린다.
- 임상 작업 흐름의 집중도를 위해 포트폴리오·면책 문구를 화면에 지속 노출하지 않는다. 가상 데이터 기반 프로토타입이며 의사결정 보조가 아니라는 범위는 README와 본 제품 문서에 유지한다.
- 요약 완료 전에 `원본 기록을 확인했습니다` 확인 상태가 필요하다.

## 10. 핵심 데이터 계약

```text
HandoverComparison
├─ patient: id, name, room, age, sex, diagnoses
├─ interval: previousRecordedAt, currentRecordedAt
├─ status: ready | no_previous | no_changes | partial
├─ dataWarnings[]
├─ changes[]
│  ├─ id, category, changeType, reviewPriority
│  ├─ label, previousValue, currentValue, delta
│  └─ evidence: fieldPath, previousRecordedAt, currentRecordedAt

HandoverSummary
├─ mode: deterministic | ai
├─ sections: situation, background, assessment, recommendation
├─ evidenceIds[]
└─ warnings[]

HandoverApiResponse
├─ comparison: HandoverComparison
└─ summary: HandoverSummary
```

Python과 TypeScript는 같은 JSON 필드명을 사용하며 API 계약 테스트로 고정한다.

## 11. 이번 마일스톤 완료 기준

1. 5명 fixture 모두에서 이전·현재 구조화 비교 결과가 생성된다.
2. 추가/중단/변경된 투약과 신규/삭제된 진단·메모가 구분된다.
3. 모든 변화 항목이 원본 필드와 양쪽 기록 시각으로 추적된다.
4. 1440px 화면에서 환자 선택, 비교, 요약 검토가 한 작업공간에서 완료된다.
5. AI 키 없음과 API 실패에서도 deterministic 요약이 보인다.
6. 주요 상태를 색상 없이도 구분할 수 있다.
7. Vercel Preview 빌드와 API smoke test를 통과한다.

## 12. 현재 범위 밖

- 실제 EMR 연결과 실제 환자정보
- 인증, 권한, 전자서명, 감사 로그
- 투약 투여·보류 기록 작성
- 처방, 검사, 영상, I/O, 낙상 등 현재 스키마에 없는 임상 데이터
- 자동 Recommendation 생성과 임상적 악화 판정
- 다중 사용자 공유와 장기 영속 저장
