# CareNote 통합 제품 데모

기준일: 2026-09-23. 인수인계와 차팅의 기존 구현을 연결하는 **별도 공개 제품 데모**이며 실제 병원 운영 EMR이 아니다. CareNote는 이번 통합 작업의 제품명이다. 기존 두 서비스의 운영 주소와 원본 차팅 저장소는 이번 배포로 교체하지 않는다.

## 사용자 흐름

1.0.2의 제품 소개는 중앙 히어로와 같은 합성 환자의 근무 준비·원본 근거·간호기록 미리보기로 구성한다. 미리보기는 실제 작업공간과 구분된 예시이며, 체험 링크로 실제 `/workspace` 기능을 연다. 데모 기능·저장 정책의 변경은 없다. 디자인 근거는 `docs/decisions/2026-09-23-carenote-saas-landing.md`에 기록한다.

1. `/` 제품 소개에서 작업공간을 연다.
2. `/workspace`에서 환자를 선택하고 이번 근무의 새 결과, 예정 항목, 명시 전달 요청을 확인한다.
3. 근거를 선택해 원본 시점·필드·이전/현재 값을 대조한다. 최근 변화는 필요할 때 펼친다.
4. 같은 환자 맥락으로 환자 기록이나 간호기록으로 이동한다.
5. 지원하는 짧은 관찰 표현의 규칙 기반 초안을 검토·채택하고, 미입력 항목을 직접 작성한다.
6. `기록 추가`를 명시적으로 눌러야 미서명 데모 기록이 생긴다. 해당 서술은 근무 준비 API에 재조회되어 기록 변화로 연결된다.

`/handover`에는 기존 직전 교대 비교·휴무 복귀·SBAR·기록 편집·화면 안내를 보존했다. 새 근무 준비 화면에 이전의 전체 3열 비교 UI를 반복하지 않는다.

## 기능과 의미

| 항목 | 실제 동작 | 하지 않는 일 |
|---|---|---|
| 공통 환자 | 기존 인수인계 합성 환자 5명, 환자마다 명시적 시연 입원 식별자 | 서로 다른 원본 앱의 동명이인 자동 병합 |
| 근무 준비 | 기존 Python deterministic 규칙과 원본 상태에 따른 항목 표시 | 의료적 우선순위 판단, 새 처방·보고 필요성 추론 |
| 비교 범위 | 보유한 원본 기록 시각 중 기준 선택 | 존재하지 않는 휴무 기록 생성 |
| 확인 표시 | 해당 환자·기간·기록 버전의 읽음 상태 | 처치 수행 완료, 공식 인계 완료 |
| 검토 메모 | 준비 항목에 덧붙이는 개인 검토 메모 | 공식 간호기록 또는 처방 변경 |
| 간호기록 | 지원 단문에 한정한 규칙 기반 SOAP 초안, 수기 편집, 명시 추가 | 모든 자연어 이해, 활력징후 자동 SOAP, 자동 서명 |
| 근거 | 환자·입원 일치와 기록 시각 적합성을 확인 | 미래 근거 사용, 수정 후 출처 임의 복구 |
| 기록 연결 | 새 서술만 이후 snapshot에 투영하고 기존 활력징후·처방 유지 | 서술에서 임상 수치·투약행위 역추출 |

새 `/workspace`의 초안·추가 기록·읽음·검토 메모는 **페이지 메모리**에만 존재한다. 같은 페이지의 환자/모듈 전환에서는 보존하고 새로고침하면 초기화한다. 읽음/검토 메모는 비교 범위와 기록 버전별로 분리한다. 기존 `/handover`의 별도 세션 저장 동작은 그대로다.

## 차팅 제한

- 지원 표현만 추천한다. 복합 증상, 정정·부정의 복잡한 문장, 미지원 횟수 표현은 원문을 유지하고 직접 작성하도록 한다.
- 입력에 없는 호소, 정상 소견, 평가 또는 계획을 만들어내지 않는다. 미제공 SOAP 항목은 직접 확인·작성 대상으로 남긴다.
- 미완성 안내 표시가 남은 초안은 기록 추가할 수 없다. 가상 시연에서도 실제로 관찰하지 않은 사실을 임의로 채우지 않는다.
- LLM/API 호출은 새 차팅 모듈에 없다. 기존 `/handover`의 선택적 AI 요약은 별도 기존 기능이며, 새 배포에 OpenAI 키를 자동 복사하지 않는다.
- PRN 투여 기록은 공통 시나리오에 공급하지 않는다. 처방 정보를 실제 투여 사실로 바꾸지 않는다.
- 수정하거나 모듈을 나갔다 돌아온 초안의 자동 근거는 추측하여 복원하지 않는다.

## 실패와 안전한 상태

1.0.1 문구 정리에서 장식 소제목·중복 설명·정상 완료 배너를 제거했다. 확인 표시에는 `확인 = 읽음`, 기록 추가 옆에는 새로고침 초기화·미서명을 짧게 표시한다. 안내 축약은 아래 기능·저장 정책의 변경이 아니다.

- 늦게 도착한 이전 환자의 응답은 표시하지 않는다.
- 기록 추가 후 재조회 실패 시 새 기록과 초안은 지우지 않으며, 이전 결과는 최신이 아님을 표시한다.
- 잘못된 시간, 다른 환자/입원의 근거, 미래 기록의 근거 연결은 거부한다.
- API payload에는 번들 합성 데이터와 사용자가 이 데모에 입력한 서술이 포함된다. 실제 환자정보를 입력하지 않는다. 서버에 영구 저장하지 않는다.

## 개발 및 검증

Next 프런트엔드와 기존 FastAPI를 별도로 실행한다. 개발 환경에서만 `CARENOTE_API_ORIGIN`으로 API를 프록시한다. Vercel에서는 `vercel.json`의 기존 Python Function rewrite를 사용한다.

```powershell
# 격리된 Python 환경을 활성화한 터미널
python -m uvicorn api.index:app --host 127.0.0.1 --port 8017

# 다른 터미널
$env:CARENOTE_API_ORIGIN='http://127.0.0.1:8017'
pnpm dev --hostname 127.0.0.1 --port 3017

# 실제 두 서버를 사용하는 브라우저 테스트
$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:3017'
pnpm test:e2e
```

자동 검사: Vitest, ESLint, TypeScript, Next build, Python unittest, harness, 실제 API 연결 E2E, 기존 인수인계 회귀 E2E. 테스트 건수는 해당 실행 시점의 기술적 검증이지 사용자 효과나 임상 안전성 입증이 아니다. 최신 실행 결과와 배포 확인은 별도 검증 기록에 남긴다.

## 협업과 기여 기록

사람 참여자는 사용자 1명이다. 사용자가 방향·요구·검수 기준을 제시했으며 AI 에이전트가 구현과 검증을 보조했다. AI 작업을 사람 팀원의 협업 경험으로 표현하지 않는다.

- 감독: 공통 계약, 원본 보존, 환자/기록 연결, 라우팅, 독립 리뷰, 전체 검증, 배포.
- 차팅 담당 AI: 기존 차팅 도메인 재사용, 제어형 편집기, 입력 문법 및 시간/근거 경계 수정.
- UI 담당 AI: 공통 작업공간 및 랜딩 페이지의 지정 파일 구현.
- 협업 원문과 결정·수정 이력: 사용자 지정 Notion의 `CareNote 통합 제품 — 에이전트 협업·개발 기록`.

현재 사용성·시간 절감·임상 효과는 별도 측정하지 않았다. 실제 병원 도입을 위해서는 사용자 과업 검증, 접근권한/감사로그/영속저장, 병원별 기록 정책 및 연동 검토가 추가로 필요하다.
