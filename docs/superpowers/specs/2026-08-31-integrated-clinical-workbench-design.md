# 통합 임상 워크벤치 재설계 명세

- 상태: 승인됨 · 구현 기준
- 작성일: 2026-08-31
- 목표 버전: `0.7.0`
- 기준 제품: Nurse Handover Assistant `0.6.0`
- Figma 기준: `KpybGW6Y8u9TyPSv61OcM9`, node `39:3` (`Nurse EMR / Desktop`)

## 1. 목적

환자 큐, 이전·현재 기록 비교, 원본 기록 조회·입력, SBAR 인계 검토를 서로 다른 화면 조각이 아니라 하나의 간호 업무 프로그램으로 인식되게 재구성한다.

제품의 단일 핵심 작업은 그대로 유지한다.

> 선택 환자의 두 기록 사이 변화를 확인하고, 원본 근거를 추적한 뒤 인계 요약을 검토 완료한다.

Figma의 범용 EMR 내용을 복제하지 않고 전역 헤더, 환자 레일, 환자 안전 배너, 고밀도 기록지, 우측 검토 레일의 시각 문법만 현재 인수인계 기능에 맞게 적용한다.

## 2. 설계 원칙

1. **인수인계 비교가 주인공이다.** 원본 기록은 비교의 근거를 확인하고 시연 데이터를 수정하는 보조 모듈이다.
2. **한 환자, 한 작업 맥락을 유지한다.** 환자 레일, 중앙 작업공간, 인계 검토는 항상 같은 환자를 가리킨다.
3. **임상 사실을 추가로 만들지 않는다.** 알레르기, 낙상, 담당의처럼 현재 데이터 계약에 없는 정보는 Figma에 있어도 표시하지 않는다.
4. **고밀도는 장식이 아니라 구조에서 만든다.** 큰 카드, 넓은 여백, 과한 그림자를 줄이고 얇은 구획선과 정렬된 행을 사용한다.
5. **AI보다 근거를 먼저 보여준다.** 우측 레일은 `AI REVIEW`를 복제하지 않고 `인계 검토`로 명명한다. AI는 출처 태그일 뿐 제품의 주체가 아니다.
6. **기존 동작 계약을 보존한다.** deterministic 비교, 성공 시에만 기록 적용, sessionStorage, 실패 시 마지막 검증 결과 유지 규칙을 바꾸지 않는다.

## 3. 채택안과 대안

### 채택: EMR Workbench 통합형

- 네이비 전역 헤더 아래에 좌측 환자 레일, 중앙 작업공간, 우측 인계 검토 레일을 배치한다.
- 중앙 상단에 `인수인계 비교`와 `원본 기록` 모듈 탭을 둔다.
- 기존 원본 기록 드로어는 중앙의 정식 작업 모듈로 전환한다.
- 원본 기록 비교가 성공하면 자동으로 `인수인계 비교`로 돌아와 갱신된 변화와 요약을 보여준다.

이 방식은 현재 핵심 기능을 보존하면서 Figma가 가진 실제 업무 프로그램의 연속성을 가장 잘 전달한다.

### 제외: 현재 화면 단순 재스킨

기존 3열 카드 구조와 우측 드로어를 그대로 두고 색상만 변경하면 원본 기록이 별도 도구처럼 느껴지는 문제가 남는다.

### 제외: 범용 EMR 전체 모사

V/S, MAR, I&O, 간호계획 등의 비활성 메뉴를 추가하면 실제 기능처럼 오해될 수 있고 인수인계 차이 비교가 약해진다. 현재 구현된 두 모듈만 노출한다.

## 4. 정보 구조

### 4.1 데스크톱

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ NURSE HANDOVER · SHIFT REVIEW │ 일반병동 · DAY 07:00–15:00 │ 시각 · 근무중 │
├───────────────┬──────────────────────────────────────┬───────────────────────┤
│ 담당 환자     │ 환자 컨텍스트·비교 기준             │ 인계 검토             │
│ 검색          ├──────────────────────────────────────┤ 출처·근거 포함률       │
│ 환자 목록     │ [인수인계 비교] [원본 기록]         │ SBAR                   │
│ 변화/검토상태 │                                      │ Recommendation 입력    │
│               │ 선택한 중앙 작업 모듈               │ 원본 확인·검토 완료    │
└───────────────┴──────────────────────────────────────┴───────────────────────┘
```

- 전역 헤더: 높이 56px
- 환자 레일: 268px
- 인계 검토 레일: 320px
- 중앙 작업공간: 나머지 폭, 최소 0
- 바깥 패널 간 gap을 제거하고 1px 경계선으로 영역을 구분한다.
- 페이지 전체보다 각 레일과 중앙 본문이 독립적으로 스크롤된다.

### 4.2 전역 헤더

- 제품명: `NURSE HANDOVER`
- 보조명: `SHIFT REVIEW`
- 근무 맥락: `일반병동 · DAY 07:00–15:00`
- 우측: 현재 시각과 `RN · 근무중`
- 임의의 간호사 이름, 병동 번호 또는 운영 연결 상태는 만들지 않는다.
- 포트폴리오 설명과 범위 고지는 화면이 아니라 README와 제품 문서에 유지한다.

### 4.3 환자 레일

- 제목을 `환자 큐`에서 `담당 환자`로 변경한다.
- 검색은 이름, 환자 ID, 병실을 그대로 지원한다.
- 한 행은 병실·환자명, 성별/나이·첫 진단, 변화/검토 상태의 3줄로 구성한다.
- 선택 환자는 청록색 옅은 면과 좌측 3px 선으로 표시한다.
- `중요 N`, `변화 N`, `검토 완료`, `변화 없음`, `비교 불가`를 텍스트와 색상으로 함께 표현한다.
- 현재 정렬 규칙인 미검토 중요 변화 → 일반 변화 → 검토 완료를 유지한다.

### 4.4 환자 컨텍스트 배너

- 환자 ID, 환자명, 성별/나이, 병실을 첫 줄에 배치한다.
- 주요 진단과 비교 구간을 두 번째 줄에 배치한다.
- 전체 변화와 중요 변화 수는 우측의 짧은 지표로 표시한다.
- `알레르기 데이터 없음`은 임상 경고처럼 강조하지 않고 보조 정보로 표시한다.
- 기존 헤더의 `원본 기록` 버튼은 제거하고 모듈 탭으로 이동한다.

### 4.5 중앙 모듈 탭

- 탭은 `인수인계 비교`, `원본 기록` 두 개만 제공한다.
- 탭은 환자 컨텍스트 바로 아래에 고정한다.
- 현재 탭은 청록색 하단 2px 선과 옅은 선택 배경으로 구분한다.
- 탭 변경은 비교 데이터나 편집 중인 로컬 draft를 초기화하지 않는다.
- 환자를 바꾸면 `인수인계 비교` 탭으로 돌아간다.

## 5. 중앙 작업 모듈

### 5.1 인수인계 비교

- 기존 `Shift Seam`의 이전 → 변화 → 현재 구조를 유지한다.
- 큰 독립 카드보다 기록 목록에 가까운 평면 행으로 밀도를 높인다.
- 섹션 제목은 `먼저 확인`, `일반 변화`로 유지하고 각 행에 분류, 변경 유형, 이전값, 현재값, 기록 시각을 정렬한다.
- 근거 상세는 기본 접힘 상태이며 요약의 근거 링크를 선택하면 해당 행이 중앙에 오고 포커스를 받는다.
- 우선순위 색상은 임상 중증도가 아닌 검토 순서임을 기존 규칙대로 유지한다.

### 5.2 원본 기록

- 기존 우측 modal drawer를 중앙의 `PatientRecordWorkspace`로 전환한다.
- 내부의 `이전 기록`, `현재 기록` 탭과 구조화 입력 계약은 유지한다.
- 이전 기록은 읽기 전용, 현재 기록은 임상 기록 필드만 편집 가능하다.
- 장부형 섹션 코드 `PATIENT`, `V/S`, `DX`, `MED`, `NOTE`, `RECORDED AT`을 유지한다.
- `데모 초기화`와 `변경사항 비교`는 중앙 모듈 하단의 고정 action bar에 둔다.
- 비교 중에는 입력과 두 action을 잠그고 `비교 중`을 표시한다.
- 비교 성공: draft 저장 → 비교/요약 교체 → 검토 세션 초기화 → `인수인계 비교` 탭 전환.
- 비교 실패: 입력 유지 → 원본 기록 탭 유지 → 오류와 재시도 방법 표시.
- 원본 JSON은 표시하지 않는다.

## 6. 인계 검토 레일

- 너비 320px의 고정 레일로 유지한다.
- 상단에 `인계 검토`, `규칙 요약` 또는 `AI 요약`, 서버 상태를 한 줄에 배치한다.
- 첫 블록은 `근거 포함 N/N`과 진행선이다.
- SBAR는 얇은 구획선으로 구분하며 각 문장 아래의 근거는 기본 접힘 상태다.
- 근거 링크는 중앙이 원본 기록 탭이어도 먼저 `인수인계 비교`로 전환한 뒤 해당 변화 행에 포커스를 이동한다.
- Recommendation은 자동 생성하지 않고 간호사가 직접 입력한다.
- 원본 확인과 검토 완료 action은 레일 하단에 고정해 긴 요약에서도 접근 가능하게 한다.
- `검토 완료` 상태는 환자별 브라우저 세션에만 존재한다.

## 7. 컴포넌트와 상태 경계

### 7.1 상태 소유권

`HandoverWorkspace`가 다음 화면 상태를 소유한다.

```ts
type WorkspaceMode = "comparison" | "record";
```

- 선택 환자
- 현재 중앙 모듈
- 비교 응답 override
- 환자별 review session
- record pair override와 session draft hydration
- 비교·초기화 요청 세대와 busy/error 상태

비교 API, 임상 규칙과 데이터 스키마는 변경하지 않는다.

### 7.2 컴포넌트 책임

| 컴포넌트 | 책임 |
|---|---|
| `HandoverWorkspace` | 상태 조정, 모듈 전환, 성공·실패 트랜잭션 |
| `ClinicalHeader` | 제품명, 근무 맥락, 시각 표시 |
| `PatientQueue` | 검색, 정렬, 환자 선택 |
| `PatientContextHeader` | 동일 환자 식별과 비교 구간 |
| `WorkspaceModeTabs` | 중앙 모듈 선택과 키보드 tab 동작 |
| `ComparisonWorkspace` | deterministic 변화와 Shift Seam |
| `PatientRecordWorkspace` | 이전·현재 원본 기록 조회·입력 |
| `SummaryPanel` | SBAR, 근거, 원본 확인, 검토 완료 |

`PatientRecordWorkspace`는 draft 편집 UI만 담당하고 저장·API 호출은 `HandoverWorkspace` callback으로 요청한다.

## 8. 데이터 흐름

```text
번들 가상 record pair
        │
        ├─ deterministic / API compare ──> 변화 목록 + SBAR
        │                                      │
        │                                      └─ 근거 ID ──> 변화 행 focus
        │
        └─ 원본 기록 현재값 편집
                    │
                    └─ 비교 성공 시에만
                       sessionStorage + record override + response override
```

- 자동 요청과 수동 요청은 현재 monotonic request generation 경계를 유지한다.
- 늦은 응답은 최신 환자·최신 요청과 일치하지 않으면 무시한다.
- 잘못된 sessionStorage 값은 strict record validator에서 거부한다.
- OpenAI 실패 또는 키 부재 시 deterministic 요약을 유지한다.

### 9.2 타이포그래피

- UI와 한국어 본문: `Noto Sans KR`, `Pretendard`, 시스템 sans-serif 순서의 CSS stack
- 환자 ID, 시각, 수치: `JetBrains Mono`, `Consolas`, monospace

- 운영 화면에 맞춰 자간과 줄 높이를 작게 유지하되 본문 최소 11px를 지킨다.
- 외부 폰트 다운로드 의존성을 새로 추가하지 않는다.

### 9.3 형태와 시그니처

- 기본 패널 radius 0, 입력과 action radius 3–4px
- 그림자를 기본 사용하지 않고 overlay가 필요한 경우에만 제한한다.
- 시그니처 요소는 **Shift Seam이 이어지는 임상 기록 구획선**이다. 중앙 모듈이 바뀌어도 비교 시각과 환자 컨텍스트가 유지되어 현재 업무 위치를 잃지 않게 한다.
- 장식 아이콘을 새로 만들지 않는다. 텍스트, 선, 기존 의미 기호만 사용한다.

## 10. 반응형

### 1280px 이상

- 환자 레일 268px, 중앙 flexible, 인계 검토 320px를 동시에 표시한다.
- 세 영역은 viewport 높이 안에서 독립 스크롤한다.

### 960–1279px

- 환자 레일을 220px로 축소한다.
- 인계 검토 레일을 280px로 축소해 세 영역을 계속 함께 표시한다.
- 중앙 모듈은 최소 폭을 보장하고 긴 값은 행 내부에서 줄바꿈한다.

### 959px 이하

- 전역 헤더 → 담당 환자 → 환자 컨텍스트 → 모듈 탭 → 활성 작업공간 → 인계 검토 순으로 쌓는다.
- 환자 목록은 최대 높이를 두고 내부 스크롤한다.
- 원본 기록은 overlay가 아닌 전체 폭의 인라인 작업공간이다.
- 390px에서도 medication 구조화 입력이 한 열로 재배치되고 가로 overflow가 없어야 한다.

## 11. 접근성

- 중앙 모듈 탭은 `role="tablist"`, 각 탭은 `role="tab"`, 패널은 `role="tabpanel"`을 사용한다.
- ArrowLeft/ArrowRight, Home/End로 탭을 이동하고 선택 탭에 포커스를 유지한다.
- 환자 변경 시 환자명과 비교 구간을 live region으로 알린다.
- 상태는 색상 외 라벨을 함께 사용한다.
- 근거 링크가 모듈을 전환한 뒤에도 목표 변화 행으로 포커스를 이동해야 한다.
- 모든 입력 label, visible focus ring, reduced motion 동작을 유지한다.
- 고정 레일과 action bar가 200% 확대에서 내용을 가리지 않아야 한다.

## 12. 오류와 빈 상태

- API pending: 중앙 작업 구조와 비교 시간축을 유지하고 인계 검토 action을 잠근다.
- 자동 비교 실패: 번들 검증 결과와 deterministic 요약을 유지하고 우측에 연결 상태를 표시한다.
- 원본 기록 수동 비교 실패: 원본 기록 모듈과 입력을 유지하고 action bar 위에 재시도 오류를 표시한다.
- 변화 없음: 중앙에 두 기록의 시각과 `검출된 변화가 없습니다`를 표시한다.
- 이전 기록 없음: 현재 기록만 표시하고 비교 불가 이유를 명시한다.
- 검색 결과 없음: 검색어 확인 안내와 전체 담당 환자 수를 유지한다.

## 14. 검증 기준

1. 1440px에서 헤더, 268px 환자 레일, 중앙 모듈, 320px 인계 검토가 하나의 무간격 workbench로 보인다.
2. `인수인계 비교`와 `원본 기록`을 전환해도 선택 환자와 우측 인계 검토 맥락이 유지된다.
3. 환자를 바꾸면 비교 모듈로 돌아가고 다른 환자의 미적용 draft를 노출하지 않는다.
4. 편집 비교 성공 시 갱신된 변화 행과 SBAR가 보이고 비교 모듈로 이동한다.
5. 편집 비교 실패 시 원본 기록 모듈, 입력, 마지막 검증 결과가 유지된다.
6. 요약 근거 링크는 현재 모듈과 관계없이 비교 모듈의 정확한 변화 행에 포커스를 이동한다.
7. 390px, 1024px, 1440px에서 root와 body의 수평 overflow가 1px 이하이다.
8. 키보드 탭 이동, focus 복귀, reduced motion과 화면 낭독기 이름이 유지된다.
9. Python, Vitest, Playwright, ESLint, TypeScript, Next build와 harness가 모두 통과한다.
10. Vercel Preview와 Production에서 root, health, 가상 비교 API, 전체 E2E를 통과한다.
