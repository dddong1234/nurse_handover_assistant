# 간호 인수인계 보조 워크플로

## 현재 MVP의 두 인계 흐름

### 직전 교대

1. 사용자가 담당 환자를 선택한다.
2. deterministic 로직이 이전·현재 기록의 바이탈, 투약, 진단과 메모 차이를 검출한다.
3. UI가 추가·삭제·변경과 양쪽 원본을 함께 표시한다.
4. 간호사는 변화 근거와 SBAR 초안을 검토하고 Recommendation을 직접 입력한다.
5. 원본 확인 후 검토 상태를 잠근다. AI 문장화가 실패해도 같은 변화·근거의 deterministic 요약을 유지한다.

### 휴무 복귀 — Shift Readiness

1. 사용자가 담당 환자와 마지막 근무 이후의 복귀 시작 시점을 선택한다.
2. 기존 8개 core snapshot에 같은 시각의 합성 검사·Device·투약 일정·전달 요청 상태를 결합한다.
3. `/api/handover/shift-readiness`가 별도 deterministic 규칙으로 이번 근무 항목을 만든다.
4. 화면은 `환자 상태 → 검사·결과 → Line·Device → 투약 변경 → 보고·확인` 순서로 표시한다.
5. 각 항목은 기록된 `사실 상태`와 시각을 보여주며 임상 우선순위나 조치를 추론하지 않는다.
6. 간호사는 각 항목의 `근거 보기`로 정확한 원본 snapshot·필드 또는 기간 사건을 확인한다.
7. `확인함`은 사용자가 읽었다는 세션 표시일 뿐 시행·안전·완료를 뜻하지 않는다.
8. `변화 근거` 탭은 휴무 기간의 모든 인접 변화와 P001 24건 사건을 그대로 보존한다.
9. `no_baseline`, `no_items`, `partial`, 요청 실패를 서로 다른 상태로 표시하며 실패를 빈 결과로 바꾸지 않는다.
10. 확인 ID와 수기 메모만 브라우저 `sessionStorage`에 저장하고 서버 파일시스템에는 쓰지 않는다.

## 기록 입력과 재비교

1. 최신 가상 기록은 원본 기록 화면에서 구조화해 수정할 수 있다.
2. 비교 API가 성공한 경우에만 새 비교 결과와 세션 경계를 적용한다.
3. Shift Readiness는 수정된 최신 core 기록과 canonical sidecar를 다시 결합한다.
4. 원본·약물 이름·시각 lineage가 맞지 않으면 가까운 기록을 추측하지 않고 오류로 중단한다.

## 실제 도입 전에 인간 결정이 필요한 항목

- 병원·병동별 데이터 매핑과 Shift 경계
- Line 교체, 검사, 투약, 보고를 표현하는 기관별 원천 필드
- 역할 기반 접근제어, 감사로그, 보존기간과 공유 검토 상태
- 병동별 SBAR·보고 프로토콜과 실제 임상 우선순위 기준
- 간호사 과업 실험의 목표 시간·누락률과 배포 승인 기준
